# 単体テスト仕様書作成スキル（C11 向け）

詳細設計書（`docs/specs/detailed-design.md`）に対応する単体テスト仕様書を `docs/tests/unit/<モジュール名>.md` に作成・追記するためのスキルです。

## 前提条件
- 承認済みの詳細設計書 `docs/specs/detailed-design.md`（および必要に応じ `include/*.h`）が存在すること。

## テストケースの記述形式
同ディレクトリの `template.md` に従い、見出し直下のメタブロック＋詳細セクションで記述します：

```markdown
## UT-SAMPLE-001 正常値の加算

- **ID**: UT-SAMPLE-001
- **観点**: 正常値
- **実行手段**: ctest
- **理由**: -

### 概要
...
### 前提条件
...
### 入力
...
### 期待結果
...
```

- **ID**: 見出しとフィールド双方に `UT-<MODULE>-NNN` 形式で記載（テスト関数名・CTest 出力との追跡キー）。
- **実行手段**: 原則 `ctest`（1語で固定）。自動化困難な場合のみ `manual` とし、**理由**を1行で必須記載する。
- **合否結果は仕様書に書かない**（実行結果は CTest ログが正本）。

## C11 単体テストで必須の観点
- **入力・数値境界**: 正常値、最小/最大境界（`0`, `1`, `INT32_MIN`, `INT32_MAX`, `SIZE_MAX` 等）、符号付き/符号なしオーバーフロー、空バッファ（`count == 0`）
- **ポインタ・メモリ安全**: `NULL` 引数（入力ポインタ / 出力ポインタ）、出力バッファ容量不足（切り詰め・`\0` 終端保証）、動的確保を伴う場合の確保失敗・解放確認（エラー時に出力引数を破壊しないこと）
- **ロジック・状態**: 全条件分岐、繰り返し（0回・1回・最大回数）、状態遷移、冪等性
- **出力・エラー契約**: 戻り値（`bool` / `enum` エラーコード）、出力引数の値、エラー発生時の非破壊性

## 作成プロセス
1. `read_file` で `docs/specs/requirements-definition.md`・`docs/specs/basic-design.md`・`docs/specs/detailed-design.md`（および `include/*.h`）を確認する。
2. 対象モジュール・公開関数ごとの責務と、モック/スタブ化する依存境界を整理する。
3. `template.md` を参照し、`docs/tests/unit/<モジュール名>.md` のドラフトを作成する（既存ファイルがある場合は既存内容を変更せず末尾に `## <機能名>（YYYY-MM-DD 追加）` を追記）。
4. 期待結果が観測可能な表現（具体的な戻り値・出力値・エラーコード）になっているかセルフレビューし、ユーザー承認を得て保存する。
