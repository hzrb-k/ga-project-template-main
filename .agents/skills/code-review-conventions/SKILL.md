# コードレビュー 共通規律（C11 向け）

レビューサブエージェント（`c-reviewer`）が遵守する共通規律です。観点別の C11 チェックリストは `.agents/agents/c-reviewer.md` に定義されています。

## 安全に動くための原則
- 読み取り専用を厳守する。ファイルの作成・編集・削除、およびワークスペース外参照を一切行わない。
- 秘密情報（APIキー・パスワード・個人情報）を出力しない。
- `cmake --install` / `make install` やタイムアウトなしのバイナリ直接実行を行わない。

## レビューの進め方
1. **差分確認**: `run_command` で `git diff --staged` および `git diff` を確認する（差分がなければ `git log --oneline -5`）。
2. **周辺精読**: 変更行だけでなくファイル全体・対応する公開ヘッダ（`include/*.h`）・呼び出し元・`CMakeLists.txt`・関連テストを `read_file` で読む。
3. **規約・設計照合**: `AGENTS.md`、`.agents/rules/c-style.md`、および `docs/specs/` の設計書と突き合わせる。
4. **ビルド・テスト確認**: ツールチェーンが利用可能なら `cmake --build build`（警告ゼロ）と `ctest --test-dir build --output-on-failure --timeout 10` の結果を確認する。
5. **精査して報告**: 80% 以上の自信がある問題のみ報告する。

## 報告基準とセルフチェック
ノイズを減らし重要な不具合（メモリ破壊・UB・仕様バグ）を埋もれさせないため、以下を守る：
- **80% 以上の自信がある問題のみ報告**（「念のため」レベルは出さない）。
- 変更していない既存コードの問題は、致命的なメモリ安全性／セキュリティ問題でない限り指摘しない。
- 類似する指摘は 1 件にまとめる。
- **報告前セルフチェック**:
  1. ファイル名と行番号をピンポイントで示せるか？
  2. どの入力・状態でどう壊れるかを具体的に説明できるか？
  3. 呼び出し元や上位のガード処理を確認したか？
  4. 重要度（致命的・高・中・低）を誇張していないか？

### 「致命的」「高」を付けるための証拠 3 点
以下 3 点を示せない場合は「中」へ下げるか取り下げる：
1. 問題のあるコード片と正確なファイル名・行番号
2. 壊れる具体シナリオ（例: `count == SIZE_MAX` で `count * sizeof(int)` がオーバーフローして小バッファが確保されヒープ破壊が起きる）
3. コンパイラ警告・呼び出し元チェック・既存ガードで防げない理由

### よくある「的外れな指摘」（指摘しない）
- 呼び出し元や内部 `static` 関数の契約で既に保証されている `NULL` チェック・範囲チェックの過剰要求
- 意味が自明な定数（`0`, `1`, `-1`, バイト長定数等）への「マジックナンバー」指摘
- 名前とシグネチャから意図が明らかな内部 `static` ヘルパーへのコメント要求
- `.clang-format` に準拠している書式への個人の好みによる指摘
- クリーンな変更に対して無理に指摘を捻出すること（問題なければ **`承認(APPROVE)`** が正解）

## 報告フォーマット

各指摘は以下を箇条書きで明記する：

```text
- ファイル名・行番号: src/parser.c:48
- 種別: Memory（Build / Memory / Logic / Test のいずれか）
- 重要度: 致命的（致命的 / 高 / 中 / 低 のいずれか）
- 問題: buf = realloc(buf, new_size) を直接上書きしており、確保失敗時に元のポインタを失ってメモリリークする
- 修正方針: 一時ポインタ tmp で受け、NULL 時は元の buf を解放してからエラーを返す
```

最後に必ずサマリ表と最終判定を出力する：

```markdown
## レビュー結果サマリ

| 重要度 | 件数 | 状態 |
| --- | --- | --- |
| 致命的 | 0 | 問題なし |
| 高 | 0 | 問題なし |
| 中 | 0 | 問題なし |
| 低 | 0 | 問題なし |

判定: 承認(APPROVE)
```

## 判定基準
- **承認(APPROVE)**: `致命的`・`高` がともに 0 件
- **要注意(WARNING)**: `致命的` は 0 件、`高` が 1 件以上
- **却下(BLOCK)**: `致命的` が 1 件以上（メモリ安全性・UB・コンパイル/テスト失敗は原則これに該当）
