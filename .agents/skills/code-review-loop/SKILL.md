# コードレビュー 修正ループ（C11 / `c-reviewer`）

実装エージェント自身による自己正当化バイアスを防ぐため、編集権限を持たない読み取り専用サブエージェント **`c-reviewer`** を `invoke_subagent` で起動し、`致命的`・`高` の指摘がゼロになるまで修正と再レビューを回します。

## 起動の流れ

1. **対象確定**: 変更ファイル一覧（`git diff --staged` / `git diff`）と参照すべき設計ドキュメント（`docs/specs/*.md`）を確定する。
2. **レビュー起動**: `invoke_subagent` で `TypeName: "c-reviewer"` を起動し、prompt に以下を渡す：
   - レビュー対象ファイル一覧
   - 参照すべき設計ドキュメントのパス
   - 現在の周回数（例: 1周目 / 最大3周）
   - 「編集は行わず、ファイル名・行番号・種別（`Build`/`Memory`/`Logic`/`Test`）・重要度・修正方針とサマリ表を返すこと」
3. **結果確認**: `c-reviewer` の報告から `致命的` / `高` / `中` / `低` の件数と最終判定を確認する。
4. **ループ制御**: 下記条件に従って次の一手を決定する。

## ループ制御条件（`AGENTS.md` フェーズ4 準拠）
- **継続条件**: `致命的` または `高` の指摘が 1 件以上 → メインエージェントが指摘箇所を修正し、ビルド＆テスト（`cmake --build build` / `ctest --test-dir build --output-on-failure --timeout 10`）が警告ゼロで通ることを確認したうえで、`c-reviewer` を再起動する。
- **正常終了**: `致命的`・`高` がともに 0 件になった時点でループを終了し、次フェーズへ進む。
- **異常終了**: 3 回修正しても `致命的`・`高` が残る場合はループを停止し、残存指摘と判断ポイントをユーザーへ提示する。

## 各ターンでユーザーへ報告する内容
- 周回数（現在 N 周目 / 最大 3 周）
- 重要度別の指摘件数サマリと判定（`APPROVE` / `WARNING` / `BLOCK`）
- `致命的`・`高` の指摘一覧（ファイル名・行番号・種別・修正方針）
- `中`・`低` の指摘がある場合は、今回対応するか次工程へ持ち越すかの確認事項
- 異常終了時は残存指摘と人間に判断してほしい内容
