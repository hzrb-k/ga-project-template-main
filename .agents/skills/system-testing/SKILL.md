# 総合（システム）テスト仕様書作成スキル（C11 向け）

要件定義書（`docs/specs/requirements-definition.md`）に対応する総合テスト仕様書を `docs/tests/system/<フロー名>.md` に作成・追記するためのスキルです。内部実装ではなく**利用者が観測できる振る舞い**で合否を定義します。

## 前提条件
- 承認済みの `docs/specs/requirements-definition.md` が存在すること（手順具体化のため `basic-design.md` も参照可）。

## テストケースの記述形式
同ディレクトリの `template.md` に従い、メタブロック（**`要件ID` 必須**）＋詳細セクション（**手順**必須）で記述します：
- **ID**: `ST-<FLOW>-NNN` 形式。
- **要件ID**: 要件定義書の `REQ-*` を必ず紐づける（全必須要件を 1 ケース以上でカバー）。
- **実行手段**: CTest 経由の CLI/バイナリ検証が可能な場合は `ctest`、目視や特殊環境確認が必要な場合は `manual`（`理由` を1行必須）。
- **非エンジニアにも読める表現**: 内部関数名やポインタ用語を避け、「何を実行し、どんな出力・終了コード・ファイルが得られるか」を具体的に記述する。
- **合否結果は仕様書に書かない**。

## 主な観点
- **要件網羅・正常系シナリオ**: 利用者の目的が開始から完了まで達成できるか
- **利用者視点の異常系**: 引数誤り・存在しないファイル・空入力・上限超過時に分かりやすいエラーメッセージと非ゼロ終了コードが返るか
- **境界・大量データ**: 0件・1件・上限件数でタイムアウトや異常終了しないか
- **出力の正確さ・文字コード**: 標準出力・出力ファイル・終了コードが仕様どおりか

## 作成プロセス
1. `read_file` で `docs/specs/requirements-definition.md`（および `basic-design.md`）を確認し、検証対象の全 `REQ-*` を洗い出す。
2. `template.md` を参照して `docs/tests/system/<フロー名>.md` のドラフトを作成・追記する（既存時は末尾へ `## <機能名>（YYYY-MM-DD 追加）` を追記）。
3. 要件→ケースの漏れがないか、期待結果が利用者から観測可能かレビューし、ユーザー承認を得て保存する。
