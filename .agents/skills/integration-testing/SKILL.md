# 結合テスト仕様書作成スキル（C11 向け）

基本設計書（`docs/specs/basic-design.md`）に対応する結合テスト仕様書を `docs/tests/integration/<フロー名>.md` に作成・追記するためのスキルです。

## 前提条件
- 承認済みの `docs/specs/basic-design.md` および `docs/specs/detailed-design.md` が存在すること。
- 単一モジュール内で完結する場合は省略可（その旨と理由を明記）。

## テストケースの記述形式
同ディレクトリの `template.md` に従い、メタブロック＋詳細セクション（**手順**必須）で記述します：
- **ID**: `IT-<FLOW>-NNN` 形式で見出しとフィールド双方に記載。
- **実行手段**: 原則 `ctest`（一時ファイルやサブモジュール結合を C テストで検証）、環境再現が困難な場合のみ `manual`（`理由` を1行必須）。
- **合否結果は仕様書に書かない**。

## C11 結合テストの主な観点
- **モジュール間インターフェース**: パーサ→コア→出力層のデータ受け渡し、メモリ所有権の受け渡し・解放、エラーコードの正確な伝播
- **ファイル・ストリーム I/O**: 一時ファイル読み書き、空ファイル、巨大入力、不正フォーマット、存在しないパス・読み取り不能時の安全な終了と後始末
- **再実行性・隔離**: テスト用一時ファイルはワークスペース内の一時領域（`build/` 配下等）に作成し、テスト終了時に必ず後始末すること（ワークスペース外へ一切書き込まない）
- **メモリ・リソースリーク**: 複数モジュールを跨ぐ異常終了経路でファイルハンドル（`FILE *`）やヒープメモリがリークしないこと

## 作成プロセス
1. `read_file` で `docs/specs/{requirements-definition,basic-design,detailed-design}.md` を確認する。
2. 結合対象モジュールと検証すべき接続点・障害経路を整理する（単体テストと重複させない）。
3. `template.md` を参照して `docs/tests/integration/<フロー名>.md` を作成・追記する（既存時は末尾へ `## <機能名>（YYYY-MM-DD 追加）` を追記）。
4. 観測可能な期待結果（出力内容・終了コード・戻り値・後始末）が明記されているかレビューし、ユーザー承認を得て保存する。
