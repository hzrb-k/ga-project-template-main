# 結合テスト仕様書テンプレート（C11 / CTest）

各テストケースは「メタブロック（固定フィールド）＋詳細セクション（手順必須）」で記述する。
- `実行手段` は `ctest` または `manual` の1語で固定する（`manual` 時は `理由` を1行必須）。
- テストの合否結果は本ファイルに書き戻さない。

## 1. テスト方針・対象範囲
- 結合対象モジュール: 例 `parser` ↔ `core` ↔ `io`
- 一時ファイル方針: テスト用一時ファイルは `build/test_tmp/` 等ワークスペース内に限定し、終了時に削除する。

## 2. テストケース一覧

## IT-FLOW-001 入力ファイル解析から集計結果出力までの連携

- **ID**: IT-FLOW-001
- **観点**: モジュール間連携・正常系
- **実行手段**: ctest
- **理由**: -

### 概要
入力ファイルを読み込み、`parser` で解析した値を `core` で集計し、期待どおりの結果が得られることを確認する。

### 前提条件
- ワークスペース内の一時ディレクトリにテスト用入力ファイルを配置できること

### 入力
- テスト入力ファイル: `10\n-3\n25\n`

### 手順
1. テスト用入力ファイルをワークスペース内一時パスへ書き出す
2. `parser` でファイルを開いて数値配列へ読み込む
3. 読み込んだ配列と件数を `core` の集計関数へ渡す
4. 確保した配列と一時ファイルを後始末する

### 期待結果
- 解析・集計ともに成功ステータスを返すこと
- 集計結果が `32` であること
- 終了後にメモリリークやファイルハンドル未クローズが発生しないこと

## IT-FLOW-002 不正データ混入時のエラー伝播と後始末

- **ID**: IT-FLOW-002
- **観点**: 異常系・エラー伝播
- **実行手段**: ctest
- **理由**: -

### 概要
入力ファイル途中に不正行が含まれる場合、上位へエラーコードが伝播し、確保済みリソースが漏れなく解放されることを確認する。

### 前提条件
- ワークスペース内の一時ディレクトリに不正入力ファイルを作成できること

### 入力
- テスト入力ファイル: `10\ninvalid\n25\n`

### 手順
1. 不正入力ファイルをワークスペース内一時パスへ書き出す
2. `parser` 経由で読み込み・集計フローを実行する
3. 返却エラーコードを確認し、一時ファイルを削除する

### 期待結果
- 不正フォーマットを示す規定のエラーコードが返ること
- 途中まで確保したメモリ・`FILE *` がすべて解放されること（ASan 有効時にリークゼロ）
