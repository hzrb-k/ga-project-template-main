# 要件定義書作成スキル

このスキルは `docs/specs/requirements-definition.md` を作成・レビューするための手順を定義します。

## 前提条件
- アイデア検討が完了し、`docs/ideas/idea-summary.md` が作成済みであること。

## 要件定義書の標準構成
1. プロダクト概要（背景・現在の課題・実現したいこと）
2. プロダクトコンセプト（提供価値・既存手段との差分・目指す利用体験）
3. ターゲットユーザー（想定利用者・課題と目的・利用シーン）
4. 機能要件（必須機能・任意機能・要件ID・入出力・保存/生成データ）
5. 非機能要件（信頼性/安全性・性能/メモリ制約・移植性/運用・セキュリティ）

## 作成プロセス

### 1. `idea-summary.md` の確認
`read_file` で `docs/ideas/idea-summary.md` を読み込み、背景・目的・主要機能・制約を把握します。

### 2. ドラフト生成
同ディレクトリの `template.md` を `read_file` で参照し、テンプレートに沿ってドラフトを作成します。各機能要件には必ず追跡可能な **要件ID（例: `REQ-01` / `F-01`）** を付与してください（後工程の総合テスト仕様書と紐づけます）。

### 3. レビューと改善
以下の観点でセルフレビューし、曖昧な記述を取り除きます：
- 背景・課題・実現したいことが論理的につながっているか
- 機能要件ごとに「利用者／入力／出力／エラー時の扱い」が判断可能な粒度で書かれているか
- 抽象語（「高速にする」「安全にする」「使いやすくする」等）が具体的な基準・制約に言い換えられているか
- 非機能要件（対応 OS・C11 準拠・メモリ/境界安全性・性能目標・異常終了防止）に抜けがないか
- スコープ内・スコープ外・未確定事項が区別されているか

### 4. ユーザー承認と保存
ドラフトをユーザーに提示して質疑・改善を行い、承認後に `write_file` で `docs/specs/requirements-definition.md` へ保存します。
