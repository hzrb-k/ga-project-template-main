# 基本設計書作成スキル（C11 向け）

このスキルは、承認済み要件定義書をもとに `docs/specs/basic-design.md` を作成・レビューするための手順を定義します。

## 前提条件
- 承認済みの要件定義書 `docs/specs/requirements-definition.md` が存在すること。

## 基本設計書の標準構成
不要なセクションがある場合はユーザーに確認のうえ省略してよい。

1. アーキテクチャ設計（全体構成・モジュール構成・依存関係・技術スタック）
2. インターフェース設計（CLI コマンド仕様 / 公開 C API 一覧）
3. データ・ファイル形式設計（入出力フォーマット・永続データ構造）
4. エラー処理・非機能設計（メモリ安全方針・性能・移植性・セキュリティ）

## 作成プロセス

### 1. 技術スタックと実行形態の確認
基本設計に入る前に、要件定義を踏まえて以下をユーザーに確認します（既定値を提示し差分のみ確認すると効率的）：
- **提供形態**: CLI 実行ファイル / 静的ライブラリ / ライブラリ＋CLI ラッパー
- **言語・ビルド**: C11、CMake + CTest（ビルド先 `build/`）
- **想定ターゲット環境・コンパイラ**: Windows (Clang / MSVC / MinGW) / Linux (GCC / Clang) / macOS (Clang)
- **外部ライブラリ**: 原則 C11 標準ライブラリのみ（追加依存が必要な場合は明記）
- **テスト・品質ツール**: CTest（実行手段 `ctest`）、Sanitizer（ASan/UBSan）、`clang-format`、`cppcheck`

### 2. 要件定義書の確認
`read_file` で `docs/specs/requirements-definition.md` を読み込み、全機能要件（`REQ-*`）と非機能要件を把握します。

### 3. 基本設計書ドラフトの生成
同ディレクトリの `template.md` を `read_file` で参照し、要件定義書と確認済み技術スタックを反映したドラフトを作成します。
- モジュール間の依存関係図や処理フローは Mermaid（`flowchart`）で記述する。
- 技術スタック表にプロジェクトで使用するテスト実行手段（既定 `ctest`）を明記し、後工程のテスト仕様書・`test-loop` の正本とする。

### 4. レビューと改善
以下の観点でセルフレビューを行います：
- 要件定義書の全 `REQ-*` がいずれかのモジュール・インターフェースでカバーされているか
- モジュール間の依存が循環していないか（単方向依存になっているか）
- C11 標準およびコンテナなしの安全制約（`AGENTS.md`）と矛盾がないか
- 入出力形式・エラー時終了コード・メモリ管理方針が曖昧な表現（「適切に処理する」等）になっていないか

### 5. ユーザー承認と保存
ドラフトをユーザーに提示して承認を得た後、`write_file` で `docs/specs/basic-design.md` に保存します。
