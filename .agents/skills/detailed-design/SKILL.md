# 詳細設計書作成スキル（C11 向け）

このスキルは、承認済み基本設計書をもとに実装直結の詳細設計書 `docs/specs/detailed-design.md` を作成・レビューするための手順を定義します。

## 前提条件
- 承認済みの基本設計書 `docs/specs/basic-design.md` が存在すること。

## 詳細設計書の標準構成
不要なセクションがある場合はユーザーに確認のうえ省略してよい。

1. ファイル・ターゲット構成（`include/`・`src/`・`tests/`・`CMakeLists.txt`）
2. データ構造・型定義（`struct`・`enum`・不変条件）
3. 公開関数・内部モジュール設計（シグネチャ・事前/事後条件・メモリ所有権）
4. 処理シーケンス・制御フロー（Mermaid `sequenceDiagram` / `flowchart`）
5. エラーコード・境界条件・ログ/診断出力方針
6. テスト方針の概要

## 作成プロセス

### 1. 基本設計書の確認
`read_file` で `docs/specs/basic-design.md`（および必要に応じて `docs/specs/requirements-definition.md`）を読み込みます。

### 2. 詳細設計書ドラフトの生成
同ディレクトリの `template.md` を `read_file` で参照し、実装者が迷わず C11 コードと単体テストを書ける粒度でドラフトを作成します。
- 命名規則・フォーマットの細部は `.clang-format` と `.agents/rules/c-style.md` に委ね、設計書では**設計上の判断（所有権・不変条件・エラー契約・境界値）**に集中する。
- ポインタを受け取る全関数について、**`NULL` 許容可否・バッファ長（`size_t`）・呼び出し側／関数側のどちらが `free` するか**を明記する。

### 3. レビューと改善
以下の観点でセルフレビューを行います：
- 基本設計書の全モジュール・全機能が具体的なファイル・構造体・関数へ落とし込まれているか
- すべての動的メモリ確保に対して解放責務（所有権）とエラー経路の解放方針が明記されているか
- 配列・文字列バッファの最大長・終端 `\0`・整数オーバーフロー境界が明記されているか
- 単体テストしやすい構造（I/O やグローバル状態と純粋ロジックの分離）になっているか
- 「適切に処理する」「必要に応じて対応する」といった曖昧表現が残っていないか

### 4. ユーザー承認と保存
ドラフトをユーザーに提示して承認を得た後、`write_file` で `docs/specs/detailed-design.md` に保存します。
