# C11 コーディング・安全性規約

`*.c` および `*.h` を作成・編集する際は、以下のルールを必ず遵守してください。

## 1. ヘッダとモジュール境界
- **インクルードガード必須**: すべての `.h` ファイルに `#ifndef <HEADER>_H` / `#define <HEADER>_H` / `#endif`（または `#pragma once`）を記述する。
- **最小公開**: ヘッダには公開APIと必要な型・最小限の `#include` のみを置き、内部関数・内部変数には `static` を付けて内部リンケージとする。
- **const 正当性**: 書き換えないポインタ引数には必ず `const` を付ける。

## 2. 危険関数の禁止と境界安全
- 境界チェックのない以下の標準関数は使用禁止とする：
  - `gets`, `strcpy`, `strcat`, `sprintf`, `vsprintf`, `scanf("%s", ...)`
- 代わりに長さを明示する安全な関数（`snprintf`, `vsnprintf`, `strnlen`, `memcpy`＋事前境界検査 等）を使用し、必ず終端 `\0` と戻り値（切り詰め・エラー）を確認する。
- **配列・バッファの引数設計**: ポインタで配列・バッファを受け取る関数は、必ず要素数またはバイト容量（`size_t`）を併せて受け取る。
- **サイズ・数値計算**: 乗算・加算による `size_t` や符号付き整数のオーバーフローを事前に検証する（符号付き整数オーバーフローは未定義動作）。

## 3. メモリ安全性（動的確保と解放）
- `malloc` / `calloc` / `realloc` の戻り値は**必ず `NULL` チェック**する。
- `realloc` の戻り値を元のポインタへ直接上書きしない（失敗時のメモリリーク防止のため一時ポインタで受ける）。
- すべての正常終了・異常終了経路で確保済みリソースを確実に `free` する（複数リソースを扱う関数は単一出口の `goto cleanup` パターンを推奨）。
- 二重解放（Double Free）と解放後使用（Use-After-Free）を防ぐため、解放後にスコープが残るポインタには `NULL` を代入する。

## 4. 未定義動作（UB）の禁止と警告ゼロ
- ローカル変数は宣言時に初期化する。
- ローカル変数（自動記憶域期間）へのポインタを関数から返却しない。
- 引数のポインタは参照前に `NULL` チェックする（呼び出し規約で非NULL保証を明文化した場合を除く）。
- コンパイル警告ゼロ（GCC/Clang: `-Wall -Wextra -Werror`、MSVC: `/W4 /WX`）を維持し、暗黙の型変換・未使用変数・符号付き/符号なし混在比較を残さない。
